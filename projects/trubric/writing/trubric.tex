\begin{abstract}
Efficient benchmarking estimates a system's full-benchmark performance from a small number of task executions.
Standard approaches rely solely on the binary correctness of executions from a collection of already-evaluated reference systems.
An agentic system, however, produces a rich trace for each execution that can reveal substantially more about its capabilities.
Exploiting this information requires useful trace representations.
We propose representing a trace by extracting a structured, rubric-guided summary of it with an LLM and embedding the summary with a standard text encoder.
These representations preserve correctness- and task-related signal while minimizing the presence of system identity-, model family-, and harness-related signals that dominate raw trace embeddings.
Given this representation for each task execution from all reference systems, we construct low-dimensional representations of the systems, predict a new system's score from its position among the reference systems, and combine the resulting geometric prediction with a two-parameter logistic item-response model.
On SWE-bench Verified and Terminal-Bench 2.0, the proposed estimator reduces mean absolute error from 0.13 to 0.08 ($p < 10^{-4}$) and from 0.14 to 0.12 ($p < 10^{-3}$), respectively, when provided a single random executed task relative to an item-response model alone.
These results indicate that trace geometry and correctness outcomes carry complementary predictive signal and enable more accurate benchmark score estimation from limited agent executions.
\end{abstract}

\section{Introduction}
\label{sec:intro}

The dominant paradigm of generative model use is increasingly agentic: systems plan, invoke tools, observe intermediate results, and iterate over long horizons to complete complex tasks \citep{yang2024sweagent, wang2025openhands}.
As agentic capabilities increase, so does the range of settings in which a given system might be deployed -- and, with it, the number of benchmarks on which the system must be evaluated before it can be trusted with consequential work \citep{kapoor2025hal}.
Agentic evaluation, however, is expensive as each task execution requires a properly sandboxed environment and a single task execution routinely consumes hundreds of thousands of tokens \citep{jimenez2024swebench, tbench2026} and can regularly exceed \$2{,}000 \citep{kapoor2025hal}.
% At reported per-task costs of \$0.13--\$4 \citep{kapoor2025hal}, the cost of evaluating a single system on a single benchmark can regularly exceed \$2{,}000.
Given this cost, efficient evaluation is necessary to increase the evaluation coverage of an agentic system.

Task-efficient evaluation methods (e.g., benchmark compression and anchor-item selection \citep{vivek2024anchor, maiapolo2024tinybenchmarks}, item response theory and adaptive testing \citep{kipnis2025metabench, truong2025amortized}, leveraging cached responses \citep{helm2026query}, etc.) address this problem by finding structure in item-level information available from previously-evaluated reference systems to decrease the cost of evaluating a new system.
Some task-efficient evaluation methods require only the item-level scores from reference systems \citep{vivek2024anchor, kipnis2025metabench}.
Others leverage the content of cached artifacts, such as natural language responses or residual streams, to measure the similarity of systems on a set of tasks \citep{duderstadt2023data, helm2026jailbreak, helm2026query}.
Notably, agentic workflows often produce artifacts when executing a task -- file diffs, tool calls, intermediate plans, and error messages -- recorded together in an execution trace that can be used to this effect.
Unfortunately, existing methods for using cached artifacts rely on off-the-shelf embedding functions that are not immediately well-suited for representing traces.

We make two primary contributions:
\begin{enumerate}
[wide, labelwidth=1pt, labelindent=12pt]
\setlength{\itemsep}{1pt}\setlength{\parskip}{0pt}
    \item \textbf{\trubric{} trace representations.} We introduce \trubric{} (\emph{trace rubric}): a trace representation constructed by extracting a task specific structured summary of each trace with an LLM and embedding the summary with a standard text encoder.
    We show that \trubric{} embeddings preserve information relevant to the task and behavior of the system while minimizing system-, model family-, and harness- specific signal across seven modern text encoders.
    \item \textbf{Task-efficient evaluation using cached traces.} Given the \trubric{} embeddings from a set of tasks for a target system and a collection of reference systems, we evaluate their utility for predicting the target system's full-benchmark score on SWE-bench Verified and Terminal-Bench 2.0 under three different agentic system evaluation protocols.
    We find that \trubric{}-based estimators, combined with an item-response model, reduce single-task mean absolute error from 0.13 to 0.08 ($p < 10^{-4}$) and from 0.14 to 0.12 ($p < 10^{-3}$) on the two benchmarks, respectively, and are nearly always better than baselines at any task budget (Table \ref{tab:hero}).
\end{enumerate}

\subsection{Problem statement}
\label{sec:problem}

For our purposes, an agentic system $f \in \mathcal{F}$ is a random mapping from a task space $\mathcal{Q}$ to a trace space $\mathcal{X}$.
A benchmark is a fixed collection of tasks $Q^{*} = \{q_{1}, \hdots, q_{M}\} \subset \mathcal{Q}$.
Each trace is evaluated by the benchmark's trace-level scoring function $s: \mathcal{X} \to \{0, 1\}$ and the system is evaluated by its benchmark score $ y(f) = \frac{1}{M} \sum_{j=1}^{M} \mathbb{E}\left[ s(f(q_{j})) \right] $
where the expectation is with respect to the randomness of $f$.
We write $y$ for $y(f)$ when the context is clear.

When evaluating a new system, we typically have access to $ \mathcal{D} = \left\{ \{ (x_{ij}, y_{ij}) \}_{j=1}^{M} \right\}_{i=1}^{n} $, the traces and trace-level scores of $n$ previously-evaluated reference systems $f_{1}, \hdots, f_{n}$,
where $x_{ij} \sim f_{i}(q_{j})$, $y_{ij} = s(x_{ij})$ and $y_{i} = y(f_{i}) $.
For the target system $f_{0}$, we observe traces (and, optionally, trace-level scores) on only a subset $Q \subset Q^{*}$ of $|Q| = m \ll M$ tasks and our goal is to estimate the system's full benchmark score $ y_{0} $ using only the target's $m$ executions and $\mathcal{D}$.

\section{Methods}
\label{sec:method}
We first present \trubric{} and compare it to baseline trace embedding functions. We then describe constructing representations of the systems $ f_{0}, f_{1}, \hdots, f_{n} $ based on \trubric{} embeddings that can be used to train a simple regressor in $ \mathbb{R}^{d} $ for efficient benchmarking.

\subsection{Task-specific rubrics for representing traces}
\label{sec:method-trubric}

A trace representation for benchmark prediction should place two traces close together when they reflect similar execution behavior on a task.
Concretely, we consider five attributes of a trace that a representation might encode: i) task (i.e., which task the trace corresponds to), ii) correctness (i.e., whether the trace produced a correct output), iii) system identity (i.e., which system produced the trace), iv) model family (i.e., the family of the underlying generative model), and v) harness (i.e., the harness used to produce the trace).
For efficient benchmarking with traces, an ideal representation encodes (i) and (ii) but not (iii)--(v).
\trubric{} constructs such a representation in two stages.

First, for each task $q_{j}$, an LLM is prompted with the task description to instantiate a task-specific rubric: a set of $K$ fields $R_{j} = (r_{j}^{(1)}, \hdots, r_{j}^{(K)})$, where each field describes one aspect of execution behavior (e.g., how the relevant code was localized).
Rubrics are shared across all systems and field names are shared across tasks.
Unless otherwise stated, we use $K = 6$ fields.

Second, for each trace $x_{ij}$ we use an LLM to produce a short summary $z_{ij}^{(k)} $ for each field.
The summary of each field is then embedded separately with a semantic embedding model $g: \mathcal{X} \to \mathbb{R}^{p} $ and concatenated to yield the trace representation $\phi(x_{ij}) = ( g(z_{ij}^{(1)}), \hdots, g(z_{ij}^{(K)})) \in \mathbb{R}^{K \cdot p} $.

To quantify what a representation encodes, we train class-balanced linear classifiers to predict each of the five attributes of a held-out trace from its embedding.
Classifiers for system-level attributes (iii)--(v) are evaluated on held-out tasks.
Classifiers for (i) and (ii) are evaluated on held-out groups of systems.
We use cached traces from the SWE-bench Verified leaderboard \citep{openai2024verified}, with DeepSeek-V4-Flash \citep{deepseek2026v4} as both the rubric generator and summarizer.
We compare the quality of the \trubric{} embeddings, using $ g $ to embed the start and end of a raw trace, and generic rubric-based embeddings along axes (i)--(v) in Figure \ref{fig:radar}.
Relative to baselines, \trubric{} preserves (i) and (ii) while mitigating (iii)--(v) across seven modern text encoders.
Appendix~\ref{app:traces} provides a complete worked example (i.e., a task description, its \trubric{}, and extractions for two traces) and more detailed descriptions of the classification tasks.

\subsection{Inference in the Product Kernel Perspective Space}
\label{sec:method-pkps}

Given trace representations, we represent \emph{systems} following the Product Kernel Perspective Space (PKPS) construction \citep{anonpkps}.
Before constructing the geometry, trace representations are centered by subtracting task-level means -- the average across systems for each task and field -- removing content shared by every attempt of a task and emphasizing differences in behavior.
Let $\tau$ denote a text embedding of the task description and $\kappa_{\sigma}(q, q') = \exp\left(-\| \tau(q) - \tau(q') \|^{2} / 2\sigma^{2}\right)$ a Gaussian kernel on tasks.
For systems $f_{a}$ and $f_{b}$ observed on task sets $Q_{a}$ and $Q_{b}$, define the kernel-weighted similarity
\begin{equation*}
\langle a, b \rangle = \frac{\sum_{q \in Q_{a}} \sum_{q' \in Q_{b}} \kappa_{\sigma}(q, q') \, \langle \phi(x_{aq}), \phi(x_{bq'}) \rangle}{\sum_{q \in Q_{a}} \sum_{q' \in Q_{b}} \kappa_{\sigma}(q, q')}
\end{equation*}
and the corresponding squared distance $\delta^{2}(a, b) = \langle a, a \rangle + \langle b, b \rangle - 2 \langle a, b \rangle$.
Collecting the distances $\delta(a, b)$ for all pairs of systems yields the $(n+1) \times (n+1)$ pairwise distance matrix $\Delta$.
Applying classical multidimensional scaling (MDS) to $\Delta$ yields $d$-dimensional Euclidean representations $\psi_{0}, \psi_{1}, \hdots, \psi_{n} \in \mathbb{R}^{d}$ of the target and reference systems.
We then fit a ridge regressor from the reference representations $\psi_{1}, \hdots, \psi_{n}$ to their benchmark scores $y_{1}, \hdots, y_{n}$ and estimate $\hat{y}_{\mathrm{geom}}$ by evaluating the fitted regressor at $\psi_{0}$; reference predictions are made leave-one-out via the hat matrix so that they remain honest.
All hyperparameters -- the bandwidth $\sigma$, the dimension $d$, and the ridge penalty -- are selected by treating each reference system as a pseudo-target, predicting its score from the remaining references, and minimizing the mean reference error.
No target labels are used at any point, so the geometric estimator applies even when the target's executions cannot be graded.

As a score-only baseline and blending partner we use a two-parameter logistic (2PL) item-response model \citep{birnbaum1968some}: $\mathbb{P}(y_{ij} = 1) = \mathrm{logistic}\left(a_{j} (\theta_{i} - b_{j})\right)$ with item discriminations $a_{j}$ and difficulties $b_{j}$ fit on $\mathcal{D}$, the target ability $\theta_{0}$ estimated from its $m$ graded executions, and $\hat{y}_{\mathrm{IRT}}$ given by the average predicted success probability over $Q^{*}$.
The combined estimator is the convex blend $\hat{y} = \alpha \, \hat{y}_{\mathrm{IRT}} + (1 - \alpha) \, \hat{y}_{\mathrm{geom}}$, with $\alpha \in [0, 1]$ selected by the same reference-pseudo-target procedure.
For adaptive task selection, tasks are chosen sequentially to maximize Fisher information about the target's ability under the reference-fit 2PL model.

\paragraph{Rubric-based preprocessing produces more useful trace representations.}
We compare embeddings of raw traces with embeddings of structured summaries produced using either a generic rubric or a task-specific rubric, \trubric{}.
Figure~\ref{fig:radar} shows that both rubric constructions reduce recoverable information about system identity, model family, and harness while retaining task and correctness information.
As discussed in Section~\ref{sec:intro}, these attributes can introduce nuisance variation into trace similarity, obscuring similarities in how systems execute tasks.
Task-specific rubrics generally produce a larger reduction in identity-related signals than generic rubrics.
This qualitative pattern persists across seven embedding functions with little overall variation, although the precise magnitudes differ.

These differences are also reflected in the system-level geometry.
Figure~\ref{fig:pkps} shows a clearer relationship between system position in the embedding space and benchmark score for \trubric{} than for raw-trace embeddings.
In Figure~\ref{fig:protocols}, prediction error decreases more rapidly with additional tasks when using \trubric{} representations than when using raw-trace embeddings.
On SWE-bench Verified, increasing the task budget from 1 to 20 reduces geometry-only MAE from .081 to .060 for \trubric{}, compared with .099 to .089 for raw traces.
Table~\ref{tab:hero} further shows that generic rubrics are competitive on SWE-bench, particularly at small budgets, though task-specific rubrics provide larger improvements on Terminal-Bench 2.0.

\paragraph{Trace geometry alone supports task-efficient benchmark prediction.}
Table~\ref{tab:hero} and Figure~\ref{fig:protocols} show that rubric-based trace geometry predicts full-benchmark performance more accurately than the sample score across small task budgets.
Under leave-one-family-out evaluation, this advantage holds from 1 through 10 randomly selected tasks on both benchmarks.
The geometric estimator also outperforms the population-mean baseline, indicating that its accuracy reflects useful differences between systems rather than just regularizing towards the average reference score.
We emphasize that these geometric methods \emph{only} require the target's trace content, and \emph{not} its correctness labels, which means that these methods are applicable in settings where grading (even a small number of) target tasks is infeasible (due to e.g.\ cost, lack of expertise, etc.), provided scored reference systems are available.

Trace geometry can also outperform IRT, which already exploits the correctness patterns of reference systems.
On SWE-bench, geometry remains more accurate through 10 random tasks (Figure~\ref{fig:protocols}).
On Terminal-Bench, geometry outperforms IRT at one task, but IRT is more accurate from three tasks onward.
The advantage of trace geometry over outcome-only methods is largest when few target executions are available, while its relative performance at larger budgets varies by benchmark.

\paragraph{Combining trace geometry with correctness outcomes improves prediction beyond either source alone.}
The two estimators exhibit different behavior as the task budget grows: geometric predictions are informative with very few executions, while IRT improves substantially as the number of tasks increases.
We combine the geometric and IRT predictions using the weighting procedure described in Section~\ref{sec:method}, referring to the resulting estimator as IRT $+$ \trubric{}.
Figure~\ref{fig:protocols} shows that combining their predictions improves accuracy across evaluated budgets.
At five random tasks on SWE-bench, IRT $+$ \trubric{} achieves .063 MAE, compared with .069 for geometry alone and .088 for IRT.
On Terminal-Bench -- where IRT is relatively stronger -- the combination achieves .090, compared with .107 for geometry and .097 for IRT.

The improvement therefore extends beyond choosing whichever method performs better on a particular benchmark.
These results support the complementary predictive value of execution content and correctness outcomes.
The broad pattern persists across the system-, family-, and harness-exclusion protocols in Figure~\ref{fig:protocols}, although the size of the improvement varies.
As Table~\ref{tab:hero} shows, IRT $+$ \trubric{} is best or near-best across the reported settings, though its advantage over IRT generally shrinks as the number of correctness observations increases.

\paragraph{Trace-informed estimation reduces the cost of reaching a given prediction accuracy.}
Figure~\ref{fig:cost} translates the error curves into execution costs, illustrating how more informative estimates can reduce the number of tasks required for a desired accuracy.
For this comparison, we assume a cost of \$2 per agent execution.
On SWE-bench, IRT $+$ \trubric{} reaches an MAE below .10 with one random task, compared with five tasks for IRT and twenty for the sample score -- the smallest tested budgets meeting this threshold.
This corresponds to estimated target execution costs of \$2, \$10, and \$40, respectively.

Combining trace information with adaptive sampling also reduces cost at a more stringent accuracy level: five adaptive tasks with IRT $+$ \trubric{} achieve approximately the same error as twenty random tasks with IRT, .048 MAE (Table~\ref{tab:hero}), corresponding to \$10 rather than \$40.
These comparisons concern the cost of executing tasks for a new system and assume an existing reference collection.
We assume that reference executions are available from community archives or that their acquisition cost is amortized over a large number of target evaluations.
In this calculation, we treat the cost of LLMs used to do (t)rubric summarization and the cost of API-based embedding functions as negligible compared to the cost of running the agents on the task.
These comparisons illustrate how extracting additional information from each execution can make accurate benchmark estimation feasible at substantially smaller task budgets.

\paragraph{Performance improves with larger reference libraries and adaptive task selection.}
Figure~\ref{fig:ablations}a shows that increasing the number of reference models generally improves both IRT and geometry-based estimators.
At five random tasks on SWE-bench, expanding the library from 20 to 107 systems reduces geometry-only MAE from .086 to .069 and IRT $+$ \trubric{} MAE from .081 to .063.
The contribution of geometry depends on reference availability: given a small number of reference models and a large target-task budget, IRT can outperform geometry-based methods.

Adaptive task selection provides a further improvement.
With five adaptive tasks, IRT $+$ \trubric{} achieves .048 MAE on SWE-bench, compared with .063 for five random tasks (Table~\ref{tab:hero}).
Together, Table~\ref{tab:hero} and Figure~\ref{fig:ablations}b show that adaptive selection improves both IRT and geometry-based prediction.
These findings demonstrate that trace-based estimation can be used alongside adaptive sampling.

Figure~\ref{fig:ablations}c further shows that the qualitative behavior persists across seven embedding functions.
On SWE-bench, the impact of encoder choice appears small compared with the effects of the number of target tasks and the number of reference models.

\paragraph{Broader rubrics improve average performance, though strong, small rubrics may exist.}
Figure~\ref{fig:sensitivity} varies the number of fields included in generic and task-specific rubrics, averaging performance over subsets drawn from a bank of 32 fields.
For both constructions, adding fields generally improves average prediction accuracy, with diminishing returns.
At five tasks and the larger reference library, increasing a task-specific rubric from one to six fields reduces average MAE from .090 to .081; using all 32 fields reduces it further to .077.
This pattern is consistent with an ensembling effect from combining descriptions of multiple aspects of execution.
Task-specific rubrics generally outperform generic rubrics in this experiment, with small reversals at the one-task budget.

The thin curves show that some small subsets perform substantially better than the average subset of the same size.
Each point selects the lowest average evaluation error among the tested subsets separately for that setting, averaging over probe draws and all 107 target systems even when the reference library contains 20 systems.
These retrospective selections demonstrate the existence of favorable small rubrics on the evaluation panel, rather than a validated procedure for identifying them in advance.
The selected subsets need not be nested as field count increases, so their performance need not improve monotonically.

\section{Related work}
\label{sec:related}

\paragraph{Representing agentic traces.}
The standard tools for embedding model outputs are text encoders trained on sentence-level semantic similarity \citep{reimers2019sbert, su2023instructor, nussbaum2025trainingsparsemixtureexperts}.
Agentic traces, however, implicitly or explicitly encode system metadata that may not be relevant for downstream tasks \citep{sun2025idiosyncrasies, oderinwale2026trajectories} and are not necessarily encoded well by semantic embedding models.
Instead, traces have primarily been studied through taxonomies of failure modes and actions \citep{cemri2025mast, shu2026traceprobe} and LLM judges of agent behavior \citep{zhuge2025agentjudge, mehtiyev2026beyond}.
Parallel work uses LLMs to adapt model outputs to be more naturally compared via their semantics \citep{ravfogel2024description, peng2024inbedder, benara2024qaemb}.
\trubric{} applies this to agentic traces by embedding a task-specific structured summary of each trace, preserving behavior-relevant information while minimizing the presence of system metadata.

\paragraph{Efficient benchmarking.}
Task-efficient benchmarking estimates a system's full benchmark score from a small number of executions.
The dominant paradigm for efficient benchmarking centers around item response theory (IRT) \citep{birnbaum1968some, embretson2000item}, where a target system's score is estimated with $ m \le M $ item-level scores by assigning a latent ability estimated from the relationship between a task's difficulty and discriminability based on $ \mathcal{D} $ \citep{maiapolo2024tinybenchmarks, kipnis2025metabench}.
Extensions of IRT select informative or adaptive task subsets \citep{vivek2024anchor, truong2025amortized} or apply it to agentic benchmarks directly \citep{ge2026psychometrics, ndzomga2026efficient}.
A complementary paradigm represents the systems themselves, either from their score profiles \citep{ruan2024observational, zhuang2025embedllm} or from the artifacts they produce while executing a task \citep{duderstadt2023data, acharyya2024consistent, helm2025statistical}.
For example, the Product Kernel Perspective Space (PKPS) \citep{anonpkps} represents language models as Euclidean objects obtained via multidimensional scaling of the distances between their embedded responses.
\citet{helm2026query} regress benchmark scores on similar representations and prove that the resulting predictions are task-efficient relative to the sample score.
\trubric{} enables extending geometry-based methods to agentic traces by providing an effective trace encoding.
We show that these two approaches -- score-based IRT and artifact-based PKPS -- can be combined to outperform either for any number of given executed tasks.

\subsection{Linear-probe methodology}
\label{app:probes}

For each combination of text encoder and trace representation, we assemble one embedding per trace for the executions of the 107 SWE-bench Verified systems on a fixed panel of 20 tasks (2{,}129 traces; a small number of executions are missing from the public archive).
Rubric-based representations are the concatenated per-field embeddings of Section~\ref{sec:method-trubric}; raw-trace representations embed head and tail slices of the rendered log as two blocks.
Each block is $\ell_{2}$-normalized and blocks are weighted equally.

Probes are linear classifiers trained with class-balanced squared loss and a ridge penalty; the penalty is selected along a closed-form regularization path using grouped cross-validation within the training folds.
Evaluation is five-fold grouped cross-validation with seeded, size-balanced group allocation: for the system-level attributes (iii)--(v) the groups are tasks, so probes are evaluated on tasks unseen during training, and for (i)--(ii) the groups are model families, so probes are evaluated on systems from families unseen during training.
We report balanced accuracy averaged over folds; chance balanced accuracy for a $C$-class attribute is $1/C$.
Figure~\ref{fig:radar} plots $(\mathrm{accuracy} - \mathrm{chance})/(1 - \mathrm{chance})$ for attributes (i)--(ii) and its complement for (iii)--(v), so that better-for-evaluation is always outward.
Table~\ref{tab:probes} reports the balanced accuracies underlying Figure~\ref{fig:radar}.
