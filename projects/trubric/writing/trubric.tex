\begin{abstract}
Efficient benchmarking estimates a system's full benchmark performance from a small number of task executions.
Standard approaches rely solely on the binary correctness of executions from a collection of already-evaluated reference systems.
An agentic system, however, produces a rich trace for each execution that can reveal substantially more about its capabilities.
Leveraging this information requires useful trace representations.
We propose representing a trace by extracting a structured summary of it with an LLM and embedding the summary with a standard text encoder.
These representations preserve correctness- and task-related signal while minimizing the presence of system identity-, model family-, and harness-related signals that dominate raw trace embeddings.
Given this representation for each task execution from all reference systems, we construct low-dimensional representations of the systems, predict a new system's score from its position among the reference systems, and combine the resulting geometric prediction with a two-parameter logistic item-response model.
On SWE-bench Verified and Terminal-Bench 2.0, the proposed estimator reduces mean absolute error from 0.13 to 0.08 ($p < 10^{-4}$) and from 0.14 to 0.12 ($p < 10^{-3}$), respectively, when provided a single random executed task relative to an item-response model alone and is never worse than either baseline for any given number of executed tasks.
These results indicate that trace geometry and correctness outcomes carry complementary predictive signal and together enable more accurate benchmark score estimation from limited agent executions.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Generative model use is increasingly agentic: systems plan, invoke tools, observe intermediate results, and iterate over long horizons to complete complex tasks \citep{yang2024sweagent, wang2025openhands}.
As agentic capabilities increase, so does the range of settings in which a given system might be deployed -- and, with it, the number of benchmarks on which the system must be evaluated before it can be trusted with consequential work \citep{kapoor2025hal}.
Agentic evaluation, however, is expensive.
Each task execution requires a properly sandboxed environment and a single task execution routinely consumes hundreds of thousands of tokens \citep{jimenez2024swebench, tbench2026}.
Full evaluation on a benchmark can regularly exceed \$2{,}000 \citep{kapoor2025hal}.
Given this cost, efficient evaluation is necessary to improve the evaluation coverage of an agentic system.

Task-efficient evaluation methods
% (e.g., benchmark compression and anchor-item selection \citep{vivek2024anchor, maiapolo2024tinybenchmarks}, item response theory and adaptive testing \citep{kipnis2025metabench, truong2025amortized}, utilizing cached responses \citep{helm2026query}, etc.)
address this problem by finding structure in item-level information available from previously evaluated reference systems to mitigate the cost of evaluating a new system.
Some task-efficient evaluation methods require only the item-level scores from reference systems \citep{maiapolo2024tinybenchmarks,vivek2024anchor, kipnis2025metabench, bowyer2026efficient}.
Others leverage information in cached artifacts, such as natural language responses \citep{acharyya2024consistent,helm2025statistical} or residual streams \citep{duderstadt2023data}, to measure the similarity of systems on a set of tasks.
Agentic workflows often produce artifacts when executing a task -- file diffs, tool calls, intermediate plans, and error messages -- recorded together in an execution trace that can be used to this effect.
Existing methods for using cached artifacts rely on off-the-shelf embedding functions that may better capture known model idiosyncracies \citep{sun2025idiosyncrasies} than trace functionality or behavior.
Along these lines, we make two primary contributions:
\begin{enumerate}
[wide, labelwidth=1pt, labelindent=12pt]
\setlength{\itemsep}{1pt}\setlength{\parskip}{0pt}
    \item \textbf{\trubric{} trace representations.} We introduce \trubric{} (\emph{trace rubric}): a trace representation constructed by extracting a task specific structured summary of a trace with an LLM and embedding the summary with a standard text encoder.
    We show that \trubric{} embeddings preserve information relevant to the task and behavior of the system while minimizing system-, model family-, and harness- specific signal across seven modern text encoders.
    \item \textbf{Task-efficient evaluation using cached traces.} Given the \trubric{} embeddings from a set of tasks for a target system and a collection of reference systems, we evaluate their utility for predicting the target system's full-benchmark score on SWE-bench Verified and Terminal-Bench 2.0 under three different agentic system evaluation protocols.
    We find that \trubric{}-based estimators, combined with an item-response model, reduce single-task mean absolute error from 0.13 to 0.08 ($p < 10^{-4}$) and from 0.14 to 0.12 ($p < 10^{-3}$) on the two benchmarks, respectively, and are nearly always better than baselines at every task budget (Table \ref{tab:hero}).
\end{enumerate}

\subsection{Problem statement}
\label{sec:problem}

For our purposes, an agentic system $f \in \mathcal{F}$ is a random mapping from a task space $\mathcal{T}$ to a trace space $\mathcal{X}$.
A benchmark is a fixed collection of tasks $T^{*} = \{t_{1}, \hdots, t_{M}\} \subset \mathcal{T}$.
Each trace is evaluated by the benchmark's trace-level scoring function $s: \mathcal{X} \to \{0, 1\}$ and the system has a benchmark score $ y(f) = \frac{1}{M} \sum_{j=1}^{M} \mathbb{E}\left[ s(f(t_{j})) \right] $,
where the expectation is with respect to the randomness of $f$.
We write $y$ for $y(f)$ when the context is clear.

When evaluating a new system, we typically have access to $ \mathcal{D} = \left\{ \{ (x_{ij}, s(x_{ij})) \}_{j=1}^{M} \right\}_{i=1}^{n} $, the traces and trace-level scores of $n$ previously-evaluated reference systems $f_{1}, \hdots, f_{n}$,
where $x_{ij} \sim f_{i}(t_{j})$ and $y_{i} = y(f_{i}) $.
For the target system $f_{0}$, we observe traces (and, optionally, trace-level scores) on only a subset $T \subset T^{*}$ of $|T| = m \ll M$ tasks and our goal is to estimate the system's full benchmark score $ y_{0} $ using only the target's $m$ executions and $\mathcal{D}$.

\section{Related work}
\label{sec:related}

\paragraph{Representing agentic traces.}
The standard tools for embedding model artifacts are text encoders trained on sentence-level semantic similarity \citep{reimers2019sbert, su2023instructor, nussbaum2025trainingsparsemixtureexperts}.
Agentic traces, however, implicitly or explicitly encode system metadata that may not be relevant for downstream tasks \citep{sun2025idiosyncrasies, oderinwale2026trajectories} and are therefore not necessarily encoded well by semantic embedding models.
Instead, traces have primarily been studied through taxonomies of failure modes and actions \citep{cemri2025mast, shu2026traceprobe} and LLM judges of agent behavior \citep{zhuge2025agentjudge, mehtiyev2026beyond}.
Parallel work uses LLMs to adapt model outputs to be more naturally compared via their semantics \citep{ravfogel2024description, peng2024inbedder, benara2024qaemb}.
\trubric{} applies this to agentic traces by embedding a task-specific structured summary of each trace, preserving behavior-relevant information while minimizing signal from system metadata.

\paragraph{Efficient benchmarking.}
Task-efficient benchmarking estimates a system's full benchmark score from a small number of executions.
The dominant paradigm for efficient benchmarking centers around item response theory (IRT) \citep{birnbaum1968some, embretson2000item}, where a target system's score is estimated with $ m \le M $ item-level scores by assigning a latent ability estimated from the relationship between a task's difficulty and discriminability based on $ \mathcal{D} $ \citep{maiapolo2024tinybenchmarks, kipnis2025metabench}.
Extensions of IRT select informative or adaptive task subsets \citep{vivek2024anchor, truong2025amortized}.
A complementary paradigm represents the systems themselves, either from their score profiles \citep{ruan2024observational, zhuang2025embedllm} or from the artifacts they produce while executing a task \citep{duderstadt2023data, acharyya2024consistent, helm2025statistical}.
For example, the Product Kernel Perspective Space (PKPS) \citep{anonpkps} represents language models as Euclidean objects obtained via multidimensional scaling of the distances between their embedded responses.
\citet{helm2026query} regress benchmark scores on similar representations and prove that the estimate is task-efficient relative to the sample score.
\trubric{} enables extending geometry-based methods to agentic systems by providing an effective trace encoding.
We show that these two approaches -- score-based IRT and trace-based PKPS -- can be combined to outperform either for any number of given executed tasks.

\section{Methods}
\label{sec:method}
We first present \trubric{}.
We then describe constructing representations of the systems $ f_{0}, f_{1}, \hdots, f_{n} $ based on \trubric{} embeddings that can be used to train a simple regressor in $ \mathbb{R}^{d} $ for task-efficient evaluation.
We evaluate the proposed methods in Section \ref{sec:experiments}.

\subsection{Task-specific rubrics for representing traces}
\label{sec:method-trubric}
\begin{figure}[!b]
\centering
\includegraphics[width=\textwidth]{figures/trubric_figure1_radar.pdf}
\caption{Comparisons of the properties of three different methods for embedding traces across seven different off-the-shelf text encoders: embedding the raw trace, embedding a structured summary based on a generic rubric, and embedding a structured summary based on a task-specific rubric.
    As measured by the balanced accuracy of a linear classifier, the embedding of the task-specific summary is better at removing undesirable signal while preserving relevant signal.}
\label{fig:radar}
\end{figure}

A trace representation for benchmark prediction should place two traces close together when they reflect similar execution behavior on a task.
Concretely, we consider five attributes of a trace that a representation might encode: i) task (i.e., which task the trace corresponds to), ii) correctness (i.e., whether the trace produced a correct output), iii) system identity (i.e., which system produced the trace), iv) model family (i.e., the family of the underlying generative model), and v) harness (i.e., the harness used to produce the trace).
For efficient benchmarking with traces, an ideal representation encodes (i) and (ii) but not (iii)--(v).
\trubric{} constructs such a representation in two stages.

First, for each task $t_{j}$, an LLM is prompted with the task description to instantiate a task-specific rubric.
The rubric is a set of $K$ fields $R_{j} = (r_{j}^{(1)}, \hdots, r_{j}^{(K)})$ where each field describes an aspect of execution behavior (e.g., how the relevant code was found).
Rubrics are shared across all traces for a given task and fields are shared across tasks.
An example rubric is provided in Appendix \ref{app:example}.

Second, for each trace $x_{ij}$ we use an LLM to produce a short summary $z_{ij}^{(k)} $ for each field.
The summary of each field is then embedded separately with a semantic embedding model $g: \mathcal{X} \to \mathbb{R}^{p} $ and concatenated to yield the trace representation $\phi(x_{ij}) = ( g(z_{ij}^{(1)}), \hdots, g(z_{ij}^{(K)})) \in \mathbb{R}^{K \cdot p} $.

Figure \ref{fig:radar} compares \trubric{} to two baselines along axes (i)--(v).
\trubric{} preserves desirable information (i) and (ii) while minimizing idiosyncratic information (iii)--(v).
Experiment details are provided in Section \ref{sec:experiments}.

\subsection{Inference in the Product Kernel Perspective Space}
\label{sec:method-pkps}
\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{figures/trubric_figure2_pkps.pdf}
\caption{The 2-d Product Kernel Perspective Space (PKPS) induced with raw trace embeddings (top) and the \trubric{} embeddings (bottom) under different number of reference systems and number of task executions.
    Each dot is a system colored by full benchmark score on SWE-bench Verified.
    The manifold of systems under the \trubric{} embeddings is more strongly correlated with the full benchmark score in paired settings. We report the average Mean Absolute Error (MAE) under leave-one-system-out (LOSO) protocol to quantify this observation.}
\label{fig:pkps}
\end{figure}

Given trace representations, we represent agentic systems via the Product Kernel Perspective Space (PKPS).
Before constructing the geometry of systems, trace representations are centered by subtracting the average across systems for each task and field to emphasize differences in behavior.
Let $\tau$ denote a text embedding of the task description and $\kappa_{\sigma}(t, t') = \exp\left(-\| \tau(t) - \tau(t') \|^{2} / 2\sigma^{2}\right)$ a Gaussian kernel on the embedded task descriptions.
For systems $f_{a}$ and $f_{b}$ evaluated on task sets $T_{a}$ and $T_{b}$, define the weighted similarity
\begin{equation}
\label{method:pkps}
\langle a, b \rangle = \frac{\sum_{t \in T_{a}} \sum_{t' \in T_{b}} \kappa_{\sigma}(t, t') \, \langle \phi(x_{at}), \phi(x_{bt'}) \rangle}{\sum_{t \in T_{a}} \sum_{t' \in T_{b}} \kappa_{\sigma}(t, t')},
\end{equation}
the corresponding squared distance $\delta^{2}(a, b) = \langle a, a \rangle + \langle b, b \rangle - 2 \langle a, b \rangle$, and $ \Delta_{ab} = \delta^{2}(a,b) $. With $ \Delta $ defined on $ f_{0}, f_{1}, \hdots f_{n} $, applying classical multidimensional scaling \citep{torgerson1952mds} to $ \Delta $ yields $d$-dimensional Euclidean representations $(\psi_{0}, \psi_{1}, \hdots, \psi_{n}) \in \mathbb{R}^{(n+1) \times d}$ of the systems with respect to the collective task sets.
Importantly, Eq. \eqref{method:pkps} is defined when $ |T_{a} | \neq |T_{b}| $ if both $ |T_{a}| > 0 $ and $ |T_{b}| > 0 $, so the target system is naturally represented in the same space as the reference systems.

In benchmarking settings, it is typical that $ |T_{0} | = m \ll M $ and $ |T_{i} | = M $ for all $ i \in \{1, \hdots, n\} $.
Given $ \mathcal{D} $ and $ \psi_{1}, \hdots, \psi_{n} $, we train a simple regressor on $ (\psi_{1}, y_{1}), \hdots, (\psi_{n}, y_{n})$ and apply it to $ \psi_{0} $ to obtain $ \hat{y}_{geom} $.
Figure \ref{fig:pkps} shows the $ d=2$ perspectives when using the raw-trace embeddings (top) and the \trubric{} embeddings (bottom) for different numbers of reference models and numbers of executed tasks per system.
Each dot is a system colored by its full benchmark score on SWE-bench Verified.
The \trubric{}-based PKPS contains more information, per a lower mean absolute error (MAE) on leave-one-system-out evaluation (LOSO; see Section~\ref{sec:experiments}).
Finally, we note that $ \hat{y} $ is estimated without any item-level score information.
In our experiments described in Section \ref{sec:experiments} we include a simple combination of $ \hat{y} $ and an IRT-based estimate that ignores trace information but utilizes the $ \{s(x_{ij})\} $.

\section{Experiments}
\label{sec:experiments}

We next describe the datasets we use to evaluate the trace embeddings and the trace-based geometries for efficient evaluation, introduce three different evaluation protocols relevant to agent evaluation, and describe relevant baselines.
We then evaluate \trubric{}-based estimators against these baselines across benchmarks, evaluation protocols, task budgets, and design choices.

\paragraph{Benchmark data.}
We consider two agentic benchmarks:
\begin{enumerate}
[wide, labelwidth=1pt, labelindent=12pt]
\setlength{\itemsep}{1pt}\setlength{\parskip}{0pt}
    \item \textbf{SWE-bench Verified} \citep{jimenez2024swebench, openai2024verified} consists of 500 human-validated software-engineering tasks drawn from real GitHub issues.
    Its public leaderboard includes submissions from 119 unique systems.
    We consider the 107 systems with complete public trace archives and per-task outcomes.
    We randomly downsampled to $ M = 100 $ with near-universal coverage.
    We let $ y_{i} $ be the official resolve rate over all 500 tasks.
    The full list of systems is included in Appendix~\ref{app:data}.
    \item \textbf{Terminal-Bench 2.0} \citep{tbench2026} consists of 89 command-line tasks executed under a standardized harness specification.
    Its leaderboard contains submissions from 75 systems.
    Each system attempts each task five times.
    We exclude two whose traces are not public and one duplicate submission.
    We analyze the 65 systems with at least 90\% trace coverage.
    We use a single trial's trace and binary outcome for a given (system, task) and let $ y_{i} $ be the all-trial and all-tasks mean resolve rate.
    The full list of systems is included in Appendix~\ref{app:data}.
\end{enumerate}

\paragraph{Trace embedding evaluation protocols.}
To quantify what a trace representation encodes, we train class-balanced linear classifiers to predict each of the five attributes of Section~\ref{sec:method-trubric} for a held-out trace from its embedding.
Classifiers for the system-level attributes (iii)--(v) are evaluated on held-out tasks.
Classifiers for (i) and (ii) are evaluated on held-out groups of systems.
We evaluate trace representations using the cached SWE-bench Verified traces described above and report balanced accuracy for each attribute.
Detailed descriptions of the classification tasks are provided in Appendix~\ref{app:probes}.

\paragraph{Trace embedding baselines.}
We compare \trubric{} embeddings to two baseline representations: \emph{raw trace}, which uses $ g $ to embed the start and end of each rendered trace, and \emph{generic}, which follows the two-stage construction of Section~\ref{sec:method-trubric} with fixed, task-agnostic field descriptions in place of a task-specific rubric.
Both the generic and \trubric{} representations use $K = 6$ fields, with DeepSeek-V4-Flash \citep{deepseek2026v4} as both the rubric generator and summarizer.
For the embedding function $g$, we consider seven text encoders: \texttt{text-embedding-3-small} \citep{neelakantan2022text}, \texttt{nomic-embed-text-v1.5} \citep{nussbaum2024nomic}, \texttt{bge-large-en-v1.5} \citep{xiao2023cpack}, \texttt{gte-large} \citep{li2023gte}, \texttt{e5-large-v2} \citep{wang2022e5}, \texttt{all-mpnet-base-v2}, and \texttt{all-MiniLM-L6-v2} \citep{reimers2019sbert}.
These encoders span open- and closed-source models, multiple architectures and training procedures, and embedding dimensions ranging from 384 to 1536.
The prompts and fixed field descriptions are provided in Appendix~\ref{app:prompts}.

\paragraph{Efficient benchmarking evaluation protocols.}
Modern leaderboards contain many entries that share an underlying model or harness.
To simulate the process of evaluating a new harness or a new model, we consider three different protocols with increasing conservatism: \emph{leave-one-system-out} where only the target itself is excluded from the references,
\emph{leave-one-family-out}  where references whose underlying model family matches the target's are additionally excluded, and \emph{leave-one-harness-out} where references sharing the target's harness are excluded.
Detailed descriptions of a system's assignment to a model family or harness are provided in Appendix \ref{app:data}.
Unless stated otherwise, we report leave-one-family-out.

\paragraph{Efficient benchmarking baselines.}
We compare against five baselines: the \emph{population mean} (the mean benchmark score of the reference systems, which ignores the target's executions entirely), the \emph{sample score} (the mean of the target's $m$ observed trace-level scores), \emph{IRT}, \emph{raw trace} (the PKPS pipeline applied to the raw-trace embeddings), and \emph{generic} (the PKPS pipeline applied to the generic-rubric embeddings).
IRT fits the two-parameter logistic model $\mathbb{P}(s(x_{ij}) = 1) = \mathrm{sigmoid}\left(a_{j} (\theta_{i} - b_{j})\right)$ \citep{birnbaum1968some} to the reference scores, where $\theta_{i}$ is the ability of system $f_{i}$ and $b_{j}$ and $a_{j}$ are the difficulty and discriminability of task $t_{j}$.
The target's ability is estimated from its $m$ observed trace-level scores and mapped to a benchmark score $\hat{y}_{\mathrm{IRT}}$ via a link function fitted on the references.
Finally, we consider the convex combination $ \hat{y}_{\alpha} = \alpha \, \hat{y}_{\mathrm{IRT}} + (1 - \alpha) \, \hat{y}_{geom}$, with $\alpha \in [0, 1] $ selected via cross-validation, which we refer to as IRT $+$ \trubric{}.
Implementation details for all baselines are provided in Appendix~\ref{app:baselines}.

\paragraph{Task selection methods.}
For each task budget $m$, we consider two methods for selecting the target's $m$ executed tasks.
\emph{Random} selection draws the $m$ tasks uniformly. Reported results average over 50 randomly sampled task subsets.
\emph{Adaptive} selection chooses tasks greedily using the fitted item-response model. In particular at each step, the task with the highest expected Fisher information under the current ability posterior is executed and the posterior is updated (Appendix~\ref{app:baselines}).

\subsection{Results}
\label{sec:results}

\paragraph{Rubric-based preprocessing produces more useful trace representations.}
Figure~\ref{fig:radar} shows that both generic and task-specific rubrics reduce recoverable information about system identity, model family, and harness while retaining task and correctness information.
As discussed above, these attributes can introduce nuisance variation into trace similarity, obscuring similarities in how systems execute tasks.
Task-specific rubrics produce a larger reduction in identity-related signals compared to generic rubrics.
This qualitative pattern persists across seven embedding functions.

These differences are also reflected in the quality of the system-level geometry.
Figure~\ref{fig:pkps} shows a clearer relationship between system position in the embedding space and benchmark score for \trubric{} than for raw-trace embeddings.
In Figure~\ref{fig:protocols}, prediction error decreases more rapidly with additional tasks when using \trubric{} representations than when using raw-trace embeddings.
On SWE-bench Verified, increasing the task budget from 1 to 20 reduces geometry-only MAE from 0.081 to 0.060 for \trubric{}, compared with 0.099 to 0.089 for raw traces.
Table~\ref{tab:hero} further shows that generic rubrics are competitive on SWE-bench, particularly at small budgets, though task-specific rubrics provide larger improvements on Terminal-Bench 2.0.

\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{figures/trubric_figure3_protocols.pdf}
\caption{The Mean Absolute Error (MAE) of benchmark score estimators as a function of the number of executed tasks for SWE-bench Verified (top) and Terminal-Bench 2.0 (bottom) under three different realistic evaluation protocols: leave-one-system-out (left), leave-one-family-out (center), and leave-one-harness-out (right).
    Reported MAE is the average over 50 random subsets of tasks.
    Shaded areas represent $ \pm 1 $ S.E.
    The \trubric{} and IRT ensemble dominates all methods (i.e., is never worse and is sometimes better) across all protocols, datasets, and number of executed tasks.}
\label{fig:protocols}

\paragraph{Trace geometry supports task-efficient benchmark prediction.}
Table~\ref{tab:hero} and Figure~\ref{fig:protocols} show that \trubric{}-based system geometry predicts full-benchmark performance more accurately than the sample score for small task budgets ($ m \le 10 $) and the population mean for all budgets.
The \trubric{}-based trace geometry can also outperform IRT, which exploits the correctness patterns of reference systems.
On SWE-bench, the geometry produces a more accurate estimate from 1 through 10 random tasks (Figure~\ref{fig:protocols}).
On Terminal-Bench, geometry outperforms IRT at one task, but IRT is more accurate from three tasks onward.
We emphasize that these geometric methods \emph{only} require the target's trace content, and \emph{not} its correctness labels, which means that these methods are applicable in settings where grading (even a small number of) target tasks is infeasible (due to e.g.\ cost, lack of expertise, etc.), provided scored reference systems are available.

\paragraph{Combining trace geometry with IRT is best.}
The trace-based predictions and correctness-based predictions exhibit different behavior as the task budget grows: trace-based predictions are informative with very few executions, while IRT improves substantially as the number of tasks increases.
Figure~\ref{fig:protocols} shows that combining their predictions improves prediction across all evaluated budgets and benchmarks.
At five random tasks on SWE-bench, IRT $+$ \trubric{} achieves 0.063 MAE, compared with 0.069 for geometry alone (Wilcoxon's $ p < 10^{-4} $) and 0.088 for IRT (Wilcoxon's $ p < 10^{-12} $).
On Terminal-Bench -- where IRT is relatively stronger -- the combination achieves 0.090, compared with 0.107 for geometry (Wilcoxon's $ p < 10^{-3} $) and 0.097 for IRT (Wilcoxon's $ p < 10^{-2} $).
These results suggest a complementary predictive value of execution artifacts and correctness outcomes.

The broad pattern persists across the system-, family-, and harness-exclusion protocols in Figure~\ref{fig:protocols}, although the size of the improvement varies.
As Table~\ref{tab:hero} shows, IRT $+$ \trubric{} is best or near-best across the reported settings, though its advantage over IRT generally shrinks as the number of correctness observations increases.

\paragraph{Trace-informed estimation reduces the cost of reaching a given prediction error.}
Figure~\ref{fig:cost} translates the error curves into the cost of evaluating a system.
For this comparison, we assume a cost of \$2 per agent execution \citep{jimenez2024swebench, tbench2026, kapoor2025hal} and assume both the cost of using LLMs to do (t)rubric creation and summarization and the cost of embedding the traces are negligible.
On SWE-bench, IRT $+$ \trubric{} reaches an MAE below 0.10 with one random task, compared with five tasks for IRT and twenty for the sample score.
This corresponds to estimated target execution costs of \$2, \$10, and \$40, respectively.

We also evaluate methods for comparing two systems head to head.
For each pair of systems whose true benchmark scores differ by at least 0.05, we exclude both systems from the references and ask whether an estimator correctly identifies the better system from $m$ random executions per system (right two panels of Figure~\ref{fig:cost}).
On SWE-bench, IRT $+$ \trubric{} decides 88\% of pairs correctly from a single task per system, compared with 79\% for IRT and 69\% for the sample score.
By five tasks per system, all estimators exceed 90\% and the score-based estimators are competitive or better; on Terminal-Bench, IRT is the most accurate decision rule at every tested budget.
Trace information is thus most valuable for head-to-head comparisons in the lowest-budget regime, where executing a single task per system (\$4 for the pair) already identifies the better system in nearly nine of ten pairs.

\paragraph{Performance improves with larger reference sets.}
The left panel of Figure~\ref{fig:ablations} shows that increasing the number of reference models generally improves both IRT and geometry-based estimators.
At five random tasks on SWE-bench, expanding the library from 20 to 107 systems reduces geometry-only MAE from 0.086 to 0.069 and IRT $+$ \trubric{} MAE from 0.081 to 0.063.
The contribution of geometry depends on reference availability: given a small number of reference models and a large target-task budget, IRT can outperform geometry-based methods.

\paragraph{Adaptive task selection composes with trace-based estimation.}
Adaptive task selection provides a further improvement.
With five adaptive tasks, IRT $+$ \trubric{} achieves 0.048 MAE on SWE-bench, compared with 0.063 for five random tasks (Table~\ref{tab:hero}).
Together, Table~\ref{tab:hero} and center panel of Figure~\ref{fig:ablations} show that adaptive selection improves both IRT and geometry-based prediction and further improves evaluation efficiency.

\paragraph{Prediction is insensitive to the choice of text encoder.} We evaluate the sensitivity of \trubric{}-based prediction on SWE-bench to the choice of text encoder in the right panel of Figure~\ref{fig:ablations}.
The impact of encoder choice is small (at most 0.008 MAE at any fixed setting) compared with the effects of the number of target tasks or task selection (0.081 to 0.060 from 1 to 20 random tasks; 0.063 to 0.048 for random versus adaptive selection at five tasks) and the number of reference models (0.086 to 0.069 at five tasks).

Figure~\ref{fig:sensitivity} varies the number of fields included in generic and task-specific rubrics, averaging performance over subsets drawn from a bank of 32 fields.

\subsection{Linear classification tasks}
\label{app:probes}

For each combination of text encoder and trace representation, we assemble one embedding per trace for the executions of the 107 SWE-bench Verified systems on a fixed panel of 20 tasks (2{,}129 traces; a small number of executions are missing from the public archive).
Rubric-based representations are the concatenated per-field embeddings of Section~\ref{sec:method-trubric}; raw-trace representations embed head and tail slices of the rendered log as two blocks.
Each block is $\ell_{2}$-normalized and blocks are weighted equally.

Probes are linear classifiers trained with class-balanced squared loss and a ridge penalty; the penalty is selected along a closed-form regularization path using grouped cross-validation within the training folds.

\section{Efficient benchmarking details}
\label{app:baselines}

\subsection{Score-only baselines}
\label{app:score-baselines}

\paragraph{Sample score.} The mean of the target's $m$ observed trace-level scores, $\hat{y}_{\mathrm{sample}} = \frac{1}{m} \sum_{t \in T_{0}} s(f_{0}(t))$.

\paragraph{Population mean.} The mean benchmark score of the reference systems, $\hat{y}_{\mathrm{pop}} = \frac{1}{n} \sum_{i=1}^{n} y_{i}$, which ignores the target's executions entirely.

\paragraph{Item-response model.}
We fit the two-parameter logistic model $\mathbb{P}(s(x_{ij}) = 1) = \mathrm{sigmoid}\left(a_{j} (\theta_{i} - b_{j})\right)$ to the reference score matrix by maximum a posteriori estimation, with standard normal priors on the abilities $\theta_{i}$ and difficulties $b_{j}$ and a $\mathcal{N}(0, 1/10)$ prior on the log-discriminations $\log a_{j}$ (centering the slopes at the Rasch value of one), optimized with L-BFGS.
Because the benchmark score aggregates all $M$ tasks while the model is fit on the $M$-task panel, we additionally fit a monotone link from ability to benchmark score, $y \approx \mathrm{sigmoid}(c_{1} \theta + c_{0})$, by least squares on the reference systems.
For a target, we form a posterior over ability on a dense grid -- the prior is a normal with the mean and standard deviation of the reference abilities -- update it with the likelihood of the target's $m$ observed trace-level scores, and report the posterior mean of the fitted ability-to-score link as $\hat{y}_{\mathrm{IRT}}$.

\paragraph{Adaptive task selection.}
Given the fitted item-response model, tasks are selected greedily per target: at each step, the next task is the one with the highest expected Fisher information $a_{j}^{2} \, p_{j}(\theta)(1 - p_{j}(\theta))$ under the current ability posterior, the outcome is observed, and the posterior is updated.
Random task selection instead draws $T_{0}$ uniformly; reported random-selection results average over 50 shared draws.

\subsection{Trace-geometry baselines}
\label{app:geom-baselines}

The raw-trace and generic-rubric estimators replace the \trubric{} representation $\phi$ in the pipeline of Section~\ref{sec:method-pkps} and are otherwise identical.
The raw-trace representation embeds the first and last portions of the rendered execution log as two blocks with the same encoder $g$; representations are centered by the task-level median across systems and $\ell_{2}$-normalized.
The generic-rubric representation follows the two-stage construction of Section~\ref{sec:method-trubric} with the fixed field descriptions of Appendix~\ref{app:prompts} in place of task-specific rubrics.

\subsection{Hyperparameters and cross-validation}
\label{app:hyper}

For each task draw, hyperparameters are selected by treating each reference system as a pseudo-target: its score is predicted from the remaining references (leave-one-out via the hat matrix for the ridge regressor), and the configuration minimizing the mean reference error is selected.
The candidate grids are the kernel bandwidth $\sigma^{2} \in \{\mathrm{med}/2^{k}\}_{k=0}^{8}$ where $\mathrm{med}$ is the median squared distance between task embeddings, the dimension $d \in \{8, 16\}$, and the ridge penalty $\in \{0.1, 1.0\}$.
The ensemble weight $\alpha$ is selected on a $101$-point grid over $[0, 1]$ by the same reference-pseudo-target procedure.
